# Profile maintenance guide

This repository is meant to evolve together with the learning roadmap.

## After finishing a Java topic

1. Update `ROADMAP.md`.
2. Keep only the current three roadmap steps in the header:
   - `current_focus`
   - `next`
   - `direction`
3. Do not add a technology to **Working with now** until you can explain and use it.
4. Move a technology out of **Backend roadmap** only after it has appeared in a real project.

## After finishing a project

Update the profile only if the project is worth opening.

A good portfolio repository should have:

- a short problem statement;
- exact setup instructions;
- screenshots or a demo where relevant;
- architecture / structure explanation;
- tests;
- no secrets;
- a concise list of technologies actually used.

Use `templates/PROJECT_README_TEMPLATE.md` as the starting point.

## Pinned repositories

The six pinned slots should eventually become:

1. strongest current project;
2. Java Core project;
3. OOP / Collections project;
4. SQL / PostgreSQL project;
5. Spring REST API;
6. final backend project.

Replace weak or old pins as stronger work appears.

## Things to avoid

- huge badge walls;
- fake skill claims;
- "passionate developer 🚀" filler;
- ten different statistics widgets;
- animated typing banners with generic phrases;
- tutorial clones presented as production work;
- public dumps, exports, logs or files containing personal data;
- secrets, tokens and `.env` files in public repositories.
